# ארכיטקטורה, טפסים והרחבות

## בסיס

אתר רב עמודים המופק ל-HTML סטטי באמצעות Node.js ללא חבילות צד שלישי. הקבצים הבנויים ב-`site/dist/`; קבצי המקור ב-`src/` וב-`scripts/`. נבחר בסיס קל, מהיר ונייד שאינו מחייב שירות מסוים. הקוד אינו React/Next.js ואינו דורש hydration כדי לקרוא תוכן.

## טופס קשר

שלב 1: שירות; שלב 2: שם וטלפון, ואימייל וחברה אופציונליים; שלב 3: תיאור צורך והסכמה להעברת הפרטים. חזרה שומרת ערכים. בדיקות שדות נעשות לפני מעבר שלב. נתוני טופס אינם נשמרים ב-localStorage.

### מצב WhatsApp המובנה

`contactMode: "whatsapp"`. הקוד מכין URL עם הודעה מקודדת. הגולש רואה קישור לפתיחה ומבין שהפרטים עדיין לא נשלחו. האתר אינו טוען שיש רשומה ב-CRM. הקישור נפתח ביוזמת הגולש; אין שליחה אוטומטית. שימוש עם JavaScript כבוי זמין דרך קישור WhatsApp הישיר והטלפון בעמוד.

### מצב webhook אופציונלי

1. בשרת Node בלבד: הגדירו `LEAD_WEBHOOK_URL` ב-HTTPS.
2. הגדירו `LEAD_WEBHOOK_TOKEN` אם היעד דורש Bearer token.
3. הגדירו `ALLOWED_ORIGIN` לכתובת האתר המדויקת, ללא סלאש סיום.
4. שנו את contactMode ל-webhook ובנו מחדש.
5. עדכנו את טקסט טופס הקשר ומדיניות הפרטיות: מה נאסף, לאן הוא נשלח ולמי פונים.
6. בדקו קליטה ביעד אמיתי עם נתוני בדיקה. הצלחת POST ל-webhook פירושה שהיעד החזיר תשובת הצלחה; אישור שמירה פנימי מחייב חוזה מוסכם עם אותו ספק.

השרת כולל אימות origin, JSON בלבד, מגבלת גוף 16KB, בדיקת שדות בצד שרת, honeypot, timeout והגבלת בקשות בסיסית בזיכרון. אין החזרת הצלחה כשלא הוגדר ספק או כאשר ההעברה נכשלה. ההגבלה בזיכרון מתאימה לשרת בודד; לפני פריסה מרובת מופעים יש להוסיף rate limit משותף ופתרון נגד ספאם. לוגים אינם כוללים את תוכן הפנייה.

ברירת המחדל הסטטית ב-Vercel אינה מפעילה את server.mjs ולכן אינה מספקת /api/leads. לפריסה סטטית שומרים WhatsApp, או מיישמים API ייעודי אצל ספק האחסון.

## טיוב לפני גידול

- אם מצרפים CRM: להגדיר שדות, בעלות, retention, טיפול בכפילויות ו-idempotency.
- אם מצרפים CMS: למפות services/articles לסכמה, לשמר URLs ולסנן HTML.
- אם מצרפים שירות קביעת פגישות: להשתמש ביעד אמיתי ומאושר.
- אם מצרפים סליקה: לא לאסוף כרטיס אשראי בטופס הקשר.

הרחבות אלה אינן מוצגות כפיצ'רים שכבר פועלים בגרסה המצורפת.
